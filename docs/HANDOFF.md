## 2. Setup (naya laptop)

1. Node 24, aur npm 12.2+: `npm install --global npm@12.2.0` (Node 24 ke saath npm 11 aata hai; repo `devEngines` se npm 12 maangta hai).
2. `npm install`, phir `npm run build` (packages ek doosre ka `dist` import karte hain). Envs: har `backend/<name>` (aur `frontend/<app>` jahan ho) me `.env.example` ka **LOCAL** hissa `.env` me copy karo (sirf laptop ki zaroori keys); OPTIONAL me defaults, PRODUCTION me live keys dummy values ke saath; asli live values sirf Render/Vercel me aur owner ki private `.env.production` me (RULES §2.4).
3. Checks: `npm run format:check`, `npm run lint`, `npm run typecheck`, `npm test` (backend packages ke tests asli Mongo pe chalte hain: pehle Docker Desktop kholo aur `npm run infra:up`; `verify` aur `publish` ke liye bhi). Package CLI ke tests me e2e ~4 minute aur create ~1 minute lete hain.
4. Styles ka playground: `npm run playground --workspace @beautinique/frontend-styles` (http://localhost:5180).
5. **Roz ka git flow** (owner, 2026-10-25; ARCHITECTURE §13, RULES §2): `git switch prerelease` → `git pull` → `git switch -c feat/<kaam>` → commits (Conventional Commits) → PR **`prerelease`** pe (development). Batch ready ho to PR `prerelease` → `release` (production: live + npm). Release safal (deploy + demo check) → PR `release` → `main` (sirf final code). Release pe bane commits (package release, hotfix) ke baad PR `release` → `prerelease` bhi. `main` pe kabhi seedha kaam nahi. **Chhota fix** (1–10 files: typo, doc line, flaky test, ek-do line ka bug) `prerelease` pe seedha push ho sakta hai: `git pull --rebase`, local format/lint/typecheck + us package ka test, phir push; force push kabhi nahi (poori list RULES §2).
6. Docker sirf local dev ke liye hai (owner Docker seekh raha hai; TASKS me "Docker Lesson" wale tasks owner ke saath karne hain).
7. **VS Code:** `Beautinique` folder seedha kholo (File → Open Folder), parent `BQ` nahi: VS Code nested `.vscode` nahi padhta. Repo ki `.vscode/settings.json` save pe ESLint se order theek karti hai (VS Code ka Organize Imports band) aur bekaar imports hatati hai (`source.removeUnusedImports`: sirf hatata hai, order nahi chhedta), aur `extensions.json` ESLint + Prettier extensions batata hai.
8. **Doosre AI tools:** root ka `AGENTS.md` unhe `CLAUDE.md`, HANDOFF aur RULES ki taraf bhejta hai (zyadatar tools `CLAUDE.md` nahi, `AGENTS.md` padhte hain). Unse bhi kaam rokte waqt HANDOFF update karwao; unka diff baad me review hota hai (`git log <commit>..HEAD`).

## 6. Traps (pehle hi pata ho)

- **MongoDB 8.0 aur Linux kernel 6.19+:** naye kernel pe `mongo:8.0.x` shuru hi nahi hota ("MongoDB cannot start: Linux kernel versions 6.19 and newer ...", SERVER-121912), kyunki uska tcmalloc kernel ke ek badlav se toot jaata hai. Ubuntu/Azure ke `7.0.0-xx` kernel bhi block hote hain (SERVER-136848). GitHub ke `ubuntu-latest` aur `ubuntu-24.04` dono runners kernel `7.0.0-azure` pe hain (2026-10-22), isliye runner pin karna kaam nahi aaya. **Hal:** compose ke `mongo` service me `GLIBC_TUNABLES=glibc.pthread.rseq=1` (JIRA pe bataya gaya workaround; tcmalloc safe raaste pe chalta hai). Laptop (WSL2 kernel 6.18) pe bhi yahi chalta hai. MongoDB ka asli fix aane pe ye setting hata do. CI ka start step kernel version print karta hai.
- **Naya backend package jo kisi service pe test kare** (Mongo, Valkey, aage Mailpit): `ci.yml` aur `release.yml` ke "Start MongoDB, Valkey and Mailpit" step me wo service jodo, warna CI pe uske tests "These tests need ..." se fail hote hain (server-queue ke pehle push pe Valkey chhoot gaya tha). Service shuru na ho to ye step `docker compose ps` aur uske aakhri 200 log lines print karta hai: wahi wajah batate hain.
- **Render ka build/start command dashboard se chalta hai, repo se nahi** (2026-10-26): repo me command badle par dashboard me purana raha, to deploy purane se hi fail hua. Isliye dashboard me sirf `sh scripts/render/build.sh` / `sh scripts/render/start.sh`; commands badalne ho to ye scripts badlo. Render workspace ki purani free services (BQ-Microservices, Beautinique-Gateway, BQ-Backend) owner ne 2026-10-26 ko suspend kar di; ab sirf `bq-live` chalti hai. Koi nayi free service mat chalana: saari free services 750 ghante/mahina saath me baantti hain (ARCHITECTURE §11.2). Owner ne unhe 2026-10-28 ko hata diya (TASKS T11.5).
- **Render me `<NAME>__*` key tabhi jab us deployable ka code use padhe** (2026-10-27): `loadConfig` kisi chalte deployable (abhi identity, core, gateway) ki anjaan `<NAME>__*` key ko typo maan ke start rok deta hai, aur deploy fail hota hai (identity ke `IDENTITY__MONGO_URI` pe yahi hua). Jo deployable abhi bana nahi (payments, notify), uski keys bundle nahi dekhta. Isliye payments/notify `npm run create` se banane wali PR me hi unke `configZod` me `MONGO_URI`/`REDIS_URL` jodo, warna Render pe pehle se padi keys se wo deploy fail hoga. Bina prefix wali keys (`NODE_VERSION`, `SENTRY_DSN`) pe ye check nahi.
- **Start fail + Sentry on = Render pe 15 min atka deploy** (2026-10-27): bundle start fail (jaise koi key na ho) hone pe error log hota tha, par Sentry ke khule connection process ko zinda rakhte the; na port, na exit, to Render "Port scan timeout" tak ruka (purana deploy chalta raha). Fix `backend/bundle/src/start.ts`: flush (max 2 s) ke baad `process.exit(1)`; test `monitoring.test.ts` (Sentry jo jawab na de). Fix ke release tak: deploy 15 min atke to Render logs me `bundle failed to start` dhoondho.
- **Dependabot alert 1, `deepmerge` (GHSA-gcqx-w48m-w2h4, low; 2026-10-28):** prototype poisoning tab hoti hai jab `deepmerge` me **bahar wale ka diya object** merge ho. Hamare yahan ye sirf build tool ke andar hai (`vite-plugin-pwa` → `workbox-build` 7.4.1 → `@rollup/plugin-node-resolve` 16.0.3 → `deepmerge` 4.3.1; root devDependency, delivery PWA generator ke liye), apne hi build options merge karta hai, server pe kuch nahi chalta. Chain ka har package latest pe hai aur `deepmerge` ka koi theek version nahi (4.3.1 hi aakhri); `overrides` se purana 4.1.x lagana plugin ki `^4.2.2` range todta hai. CI `npm audit --audit-level=high` isse nahi rukta. Jab `deepmerge` > 4.3.1 aaye ya `workbox-build` / `plugin-node-resolve` ise hataye, `npm run update-deps` se uthao.
- **Gateway sign-in tak fail closed hai** (2026-10-25): `access` `public` na ho to har route 401. Isliye login (M3) se pehle koi naya route jo live pe chalna chahiye, sirf `public` ho sakta hai, aur public write pe sakht rate limit + TTL soch ke (jaise demo ping: owner ka faisla). Seedha Render URL pe `/api` bina origin secret ke 403.
- **Test ya `.env.example` me secret jaisa literal** (`SECRET = '...'`, `..._SECRETS=...` lambi random-si value) gitleaks ka generic rule pakad sakta hai (entropy > 3.5): CI fail. Tests me secret `randomBytes` se runtime pe banao; laptop ki public value kam entropy wali hai (`not-a-secret-...`).
- **Dev server ka `/api` proxy origin secret bhejta hai** (`vite.config.ts`, app generator template): naya app ya proxy badlo to `headers: { 'x-origin-secret': ... }` mat hatao, warna gateway 403 deta hai.
- **BullMQ: wahi `jobId` dobara add karna chupchaap ignore hota hai jab tak pehla job Redis me hai** (`removeOnComplete` bhi job ko completion ke baad hi hatata hai, handler ka DB commit usse pehle hota hai). Jo test "wahi event dobara aaya" dikhana chahe wo pehle `queue.getJob(jobId) === undefined` ka intezaar kare, sirf DB ke effect ka nahi. Isi se CI pe `server-queue` ka "skips an event delivered again" test timeout hua (2026-10-22; laptop pe 54/54 pass hota tha, CPU load me bhi); test theek kiya, par GitHub pe naya run dekhna baaki hai.
- **Test me password wala nakli URL bhi gitleaks pakadta hai** (koi bhi Mongo ya Redis URL jisme scheme ke baad user, colon, password aur `@` ho; docs ki example bhi): CI fail. Aisa test ya doc likho to password ko URL me literal mat likho (docs me `<password>` jaisa placeholder chalta hai), ya push se pehle local scan (`gitleaks git --config .gitleaks.toml --redact .`) chala ke finding ko `.gitleaksignore` me fingerprint + wajah ke saath daalo. Push hui history badli nahi ja sakti.
- **Ctrl+S pe imports/exports ka order badal jaata hai, phir lint `Run autofix to sort these exports!` deta hai:** VS Code ka "Organize Imports" (`source.organizeImports`) `type` wale names aakhir me daalta hai, ESLint (`simple-import-sort`) unhe alphabet me beech me maangta hai; dono ladte hain. Sirf ESLint order tay kare: repo ki `.vscode/settings.json` me `source.organizeImports: "never"` hai, par wo tabhi lagti hai jab `Beautinique` folder window ka root ho. Badla hua order theek karne ke liye `npx eslint <file> --fix` phir `npx prettier --write <file>`.
- **npm 12 chahiye:** root `package.json` ka `devEngines` Node >=24 aur npm >=12.2.0 maangta hai (`onFail: error`), isliye purane npm pe `npm install` ruk jata hai. CI me bhi isi wajah se `setup-node` ka npm cache band hai (wo npm 11 se `npm config get cache` chalata hai aur `EBADDEVENGINES` aata hai); npm 12 install hone ke baad `actions/cache` `~/.npm` cache karta hai.
- **TypeScript ~6.0.3 pinned hai:** TS 7 aa gaya hai, par typescript-eslint sirf <6.1 support karta hai. Upgrade mat karna jab tak typescript-eslint support na de. `npm run update-deps` ise hold pe rakhta hai aur report me batata hai kab hold hata sakte ho; haath se `npm install typescript@latest` mat chalao.
- **ESLint factory ka naam `configs/eslint-config.js` hi rahe:** `eslint.config.js` naam dene pe ESLint use config samajh leta hai.
- **tsdown:** `fixedExtension: false` zaroori (warna platform node pe `.mjs` banta hai). CSS wale entry points arethetypeswrong ko nahi diye jate.
- **Windows:** tests ki temp folders kabhi-kabhi EPERM deti hain (retry hota hai). CLI npm ko bina shell chalata hai.
- **Fake registry wale tests:** in-process server ke saath `spawnSync` deadlock karta hai, async `spawn` use karo.
- **`npm run x --flag` (bina `--`):** npm flag ko `npm_config_*` bana deta hai; CLI `--dry-run` ko maanta hai aur baaki ko child npm se hata deta hai.
- **Docker Desktop (owner ka laptop):** install se pehle khula terminal `docker` nahi dhoondh pata; naya terminal kholo.
- **Claude ke liye:** Bash heredoc/`node -e` me backslashes aur quotes toot jaate hain; regex aur source files Write/Edit tool se likho.
- **Generator (`npm run create`) ke templates bhi repo ke niyam maante hain** (2026-10-31): naya ESLint niyam ya library lagao to `scripts/packages/lib/create/*-templates.ts` bhi badlo, aur template jo library use kare wo root `package.json` ki devDependencies me bhi ho (generator version wahin se leta hai; tests ki throwaway repo me sirf root manifest hota hai, warna "Could not find <lib> on npm"). `npm run test:scripts` ye pakadta hai: PR #36 ka pehla CI run isi pe fail hua (gateway template me `fetch`).
- **Backend apps ki export condition:** TypeScript me `customConditions: ["development"]` mat lagao: TS phir libraries (jaise arethetypeswrong) ka `.ts` source padhne lagta hai. Deployables ke `exports` me `types` source pe hai, aur Node/Vitest apni condition `beautinique-source` se source lete hain.
- **`http.request(urlString)`** URL ko pehle saaf karta hai (`..`, `%2e%2e` hat jaate hain); raw path test karna ho to `{ hostname, port, path }` do.
- **Band server ka handle** (`process.getActiveResourcesInfo()`) Windows pe ~50 ms baad hatta hai; ginti se pehle settle hone do.
