# OWNER TASKS: Beautinique

> **Status:** v1.0.46 (2026-11-25). Owner ke bahar ke kaam: wo kaam jo sirf owner kar sakta hai (account banana, env key daalna, download, provider ki setting, kisi se poochhna). Claude naya kaam yahan jodta hai, aur owner "ho gaya" kahe to yahin update karta hai (D-440).

## Kaise padhein

- **Khule kaam** (§1) kram se: sabse upar wala sabse pehle chahiye. "Kab tak" batata hai kis kaam se pehle ye chahiye.
- Kaam ho jaaye to Claude ko batayein ("OT-1 ho gaya", saath me jo nateeja ho). Claude jahan ho sake khud jaanch ke kaam ko §2 me le jaata hai, tareekh ke saath, aur jahan zaroori ho doosre docs bhi update karta hai.
- Yahan kabhi koi secret, password, key ya personal data nahi likha jaata: sirf kaam ka naam, kahan karna hai, aur "ho gaya". Secret ki value sirf provider ke dashboard ya password manager me rehti hai.
- **Aage ke kaam** (§3) abhi nahi karne: jab us module ka kaam shuru hoga, Claude wo kaam §1 me laayega. Koi account pehle se bana ho to bas batayein.

## 1. Khule kaam

Abhi koi khula kaam nahi: OT-10 se OT-14 ho gaye (do laptop ke setup ke liye, D-462). Roz ke kadam [manuals/DAILY_LAPTOPS.md](manuals/DAILY_LAPTOPS.md) me, aur secondary ke install ke sabak [LESSONS.md](LESSONS.md) §2 me.

**Claude ka kaam (2026-11-25):** secondary pe updates, lid band hone aur sleep ka band, `ufw` sirf SSH ke liye, Docker Engine Docker ke apt repo se, Windows ki GRUB entry, aur primary pe ssh hosts `bq-infra` aur `bq-infra-tunnel` aur Docker context `bq-infra` ho gaye; `infra:use -- secondary`, `infra:up -- backend` (mongo aur valkey healthy, tunnel khula, dono ne asli jawab diya) aur `infra:down` chal gaye. Secondary pe ssh password login ab band hai, sirf key chalti hai (jaancha: password se `Permission denied (publickey)`, key se login chala). `dev-data:copy` ka dump aur restore asli do Docker pe chala: secondary me 3 test documents the, local Mongo me wahi 3 pahunche (uske baad test database dono taraf se hata diya). Rule 14 ka flow `infra:up` se nahi banta tha (local Mongo chalu ho to secondary ka `infra:up` ports 27017 aur 6379 ke tunnel pe ruk jaata tha); owner ke faisle (D-462 badla) se `dev-data:copy` ab secondary ka Mongo khud bina tunnel uthata aur band karta hai, aur asli Docker pe chala (HANDOFF §2). Owner ne local Docker ka purana development data (`bq_core`, `bq_identity`, `bq_notify`, `bq_smoke_start`, 623 MB volume) nahi chahiye kaha, wo hata diya. Secondary pe `avahi-daemon` chalu hai aur ssh hosts IP ki jagah `bq-infra.local` par (OT-11). `dev-data:restore` aur tunnel ke upar asli jawab bhi chal gaye (HANDOFF §2). Docker Desktop chalu hone par Docker ka current context `desktop-linux` ho jaata hai: secondary pe kaam se pehle `npm run infra:use -- secondary`.
